# 采样算法

在游戏中采样的使用随处可见，从一个值的简单随机，到一个区域的均匀选取，都是游戏中常见的数值处理。还记得当初面试的时候，就被问了这样一道问题：要怎么从一个圆的内部均匀采样？当初回答的并不好，在说极坐标的时候思维磕磕绊绊，只记得说了 的答案。现在回顾这个问题，大概能有更好的解答，那就从圆的均匀采样说起吧。

## 伪随机算法

  
在游戏中，设计者往往不希望存在完全随机的情况，过于极端的情况出现会使得设计者不能很好地控制游戏的内容，所以往往会设计一些伪随机算法，使得游戏中的随机事件更加可控。在《DoTA》中的技能就大量使用了伪随机的算法。在《英雄联盟》中，也有[[蛮王卡暴击的经典操作](https://link.zhihu.com/?target=https%3A//www.bilibili.com/video/BV1Q44y1a7gv)]。那么伪随机是怎么设计的呢？  
对于一个随机事件的给定命中概率，为了避免出现极端情况，设计师通常希望在前期的时候，概率较低，随着次数的增加，概率逐渐增加直到概率为1，这样就可以保证在一定次数内必然会出现这个事件，同时连续命中多次的概率也会很低。概率变化的同时，还需要保证一个前提，就是随机变量的期望值不变。以[[《Dota》中设计的伪随机算法](https://link.zhihu.com/?target=https%3A//dota2.fandom.com/wiki/Random_Distribution)]为例，假设一个技能的期望命中概率为 ，那么在第一次计算的时候，命中概率为 ，如果第一次没命中，那么在第二次计算概率的时候，概率增加为 ，如果还没命中，那么第三次计算的时候，概率增加为 ，以此类推，直到概率为1。我们要计算合适的 值，满足期望值不变，下面是用python计算的代码：

```python
def get_expectation(c):
    """ 计算给定c值的期望 """
    expected_value, cur_p, accumulated_p, cnt = 0, 0, 1.0, 1
    while cur_p < 1:
        accumulated_p *= (1 - cur_p)
        cur_p = min(cur_p + c, 1)
        expected_value += cur_p * accumulated_p * cnt
        cnt += 1
    return expected_value

def get_c_by_p(probability):
    """ 根据给定的概率，计算c值 """
    target_expectation = 1.0 / probability
    l, r = 0, 1.0
    while l + 1e-6 < r:  # 二分查找到满足期望的c值
        mid = (l + r) / 2
        if get_expectation(mid) < target_expectation:
            r = mid
        else:
            l = mid
    return l

for i in range(1, 10):
    print('p= %.1f, c = %.6f, E = %.6f' % (i * 0.1, get_c_by_p(i * 0.1), get_expectation(get_c_by_p(i * 0.1))))
```

我曾经在一个射击类项目中，遇到一个这样的需求：  
- 敌人AI的命中率，会随着玩家自身的血量变化而变化，当玩家血量越低，敌人的命中率越低，当玩家血量越高，敌人的命中率越高；这样设计的目的是保证玩家在血量低的时候，能够有更多的机会逃脱，同时在血量高的时候有更大的生存压力；  
- 敌人AI的命中，希望是伪随机的，而不是完全随机的，从而尽量避免出现敌人连续命中玩家，或者一直没有命中玩家的情况。  
  
这个需求的不同之处在于，上面说的《DoTA》伪随机的本质是概率已经固定了，去找一个满足固定概率的期望的递增概率分布；而在这个问题中，概率是变化的，所以不能直接用上面的方法去计算。当时的解决方案是，在概率变化的时候，根据当前的未命中次数，按当前目标期望去重新计算 值，得到当前应有的伪随机概率。

### 强化系统的期望

抽卡是很多游戏都会有的系统，通常情况下，抽卡系统都会伴随着概率改变、保底等机制。除了抽卡以外，一些数值强化的系统也会有类似的机制。下面以一个简单的强化系统为例，来看看在概率改变的情况下，应该怎么计算期望。

下面用python来实现简单定义一个马尔可夫链：

```python
class MarkovChain(object):
    def __init__(self, transition_matrix, initial_distribution):
        self.transition_matrix = transition_matrix
        self.initial_distribution = initial_distribution
        self.states = transition_matrix.shape[0]
        assert transition_matrix.shape[0] == transition_matrix.shape[1]
        assert initial_distribution.shape[0] == transition_matrix.shape[0]

    def calc_last_state_expectation(self, iter_time=100, print_state=False):
        """ 计算最终状态的期望 """
        E = 0
        v_next = self.initial_distribution
        num_states = len(self.initial_distribution)
        for i in range(iter_time):
            for j in range(num_states):
                if j == num_states - 1:
                    continue
                E += (i + 1) * v_next[j] * self.transition_matrix[j][num_states - 1]
            v_next = np.dot(v_next, self.transition_matrix)
            if print_state:
                print("第%d次迭代后的状态分布:" % (i + 1), v_next)
        return E

    def get_prop_of_reaching_end_before_time(self, iter_time):
        """ 计算在iter_time内到达最终状态的概率 """
        v_next = self.initial_distribution
        num_states = len(self.initial_distribution)
        for i in range(iter_time):
            v_next = np.dot(v_next, self.transition_matrix)
        # 保留6位小数
        return np.round(v_next[num_states - 1], 6)

    def get_state_distribution(self, iter_time=1000):
        """ 计算指定迭代次数后的状态分布 """
        v_next = self.initial_distribution
        for i in range(iter_time):
            v_next = np.dot(v_next, self.transition_matrix)
        return v_next
```

### 抽卡系统的期望

  
如果大家熟悉游戏中的抽卡的话，可以知道一般地游戏的抽卡出稀有内容的概率，也只和当前的抽卡状态有关，和之前的抽卡无关，所以也可以用马尔可夫链来表示。  
以《原神》的轮换角色抽卡池子为例，只考虑5星角色池的话，原神的抽卡系统是这样设计的：

- 从第1次开始，到第73次，每次抽卡的概率都是0.6%，每次抽卡都有0.6%的概率抽到5星角色；
- 从第74次开始，每次抽卡的概率都会增加6%，也就是说第74次抽卡的概率是6.6%，第75次抽卡的概率是12.6%，以此类推，直到第89次抽卡的概率是96.6%，第90次抽卡的概率是100%；
- 抽中的5星角色中，有50%的概率是up角色，50%的概率是非up角色。

以上数据来源：《用一千万抽，揭示原神抽卡系统全部细节》([https://www.bilibili.com/video/BV19Y411W7W5](https://link.zhihu.com/?target=https%3A//www.bilibili.com/video/BV19Y411W7W5))  
  
接下来我们尝试用代码构建一下这个系统，并计算一下抽出5星角色所需要的期望（当然你也可以把所有的可能都列一个表，然后把各种可能的概率算一遍，然后得出期望）。

```python
def calc_genshin_draw_expectation():
    """ 算原神抽卡的期望 """
    # 定义状态数量
    num_states = 91  # 多定义一个状态，用于表示抽到5星

    # 初始化状态转移矩阵为零
    transition_matrix = np.zeros((num_states, num_states))
    p_change_start = 73  # 从第74个状态开始，每次抽卡增加概率
    one_draw_rate = 0.006  # 单抽概率
    # 设置前70个状态之间的转移概率
    for i in range(p_change_start):
        transition_matrix[i, i + 1] = 1 - one_draw_rate
        transition_matrix[i, num_states - 1] = one_draw_rate
    # 设置到达状态80的概率
    for i in range(p_change_start, num_states - 1):
        add_prob = one_draw_rate * 10 * (i - p_change_start + 1)  # 每次增加概率为单抽概率*10
        cur_draw_rate = min(1.0, one_draw_rate + add_prob)
        transition_matrix[i, i + 1] = 1 - cur_draw_rate
        transition_matrix[i, num_states - 1] = cur_draw_rate
    transition_matrix[num_states - 2, num_states - 1] = 1  # 第90抽必出
    transition_matrix[num_states - 1, num_states - 1] = 1  # 出5星后不再抽卡
    # 定义初始分布向量
    initial_distribution = np.zeros(num_states)
    initial_distribution[0] = 1
    # 定义马尔可夫链
    markov_chain = MarkovChain(transition_matrix=transition_matrix, initial_distribution=initial_distribution)

    # 打印状态转移矩阵
    print("状态转移矩阵:")
    print(transition_matrix)
    E = markov_chain.calc_last_state_expectation(iter_time=100, print_state=False)
    print("抽出5星所需要次数的期望:", E)
    print("抽出5星up所需要次数的期望:", E * 0.5 + E * 2 * 0.5)
    print("等价概率:", np.round(1.0 / E, 6))
    print("期望原石:", E * 160)
    # 欧皇概率
    for i in range(10, 100, 10):
        print("%d抽内抽到5星的概率:" % i, markov_chain.get_prop_of_reaching_end_before_time(i))
```

_马尔科夫链的平稳分布_

从上面的分析可以看到，对于这种有马尔可夫性的系统，我们可以使用马尔可夫链这个工具来计算到达最终状态的期望。在设置转移矩阵的时候，需要注意的是我们设置的最终状态 ，需要满足 ，也就是说，从 转移到 的概率为1，这样才能保证这个状态是一个终止状态。如果这个条件不满足的话，那么状态将可能是常返(recurrent)的，也就是说，从这个状态出发，有可能会无限次地转移回这个状态，这样的话，计算期望就会复杂一些了。  
  
值得一提的是，如果一条马尔科夫链满足不可约性(irreducible)和非周期性(non-periodic)的话，那么在经过多次转移后，这条马尔科夫链将会趋于一个平稳状态（一个状态 经过转移之后还是它本身， ），这个平稳状态就是这条马尔科夫链的极限分布。不可约性意味着任意两个状态之间都是可达的，所以这种情况不会在抽卡系统中出现。如果我们把上面的强化系统改造一下，让它在第5级的时候强化有特殊效果（不用在意是什么，就当是策划临时增加的）并保留在第5级，同时有90%的概率掉到第4级，那么这个系统就满足了不可约性，因为第5级可以强化到第4级，第4级可以强化到第5级或一直失败到第1级，所以任意两个状态之间都是可达的。这个时候，转移矩阵就变成了：  
  
  
  
用python算一下平稳状态分布：

```python
def calc_example_enhance_station_distribution():
    transition_matrix = np.array([
        [0, 1, 0, 0, 0],
        [0.25, 0, 0.75, 0, 0],
        [0, 0.5, 0, 0.5, 0],
        [0, 0, 0.75, 0, 0.25],
        [0, 0, 0, 0.9, 0.1],
    ])
    initial_distribution = np.array([1, 0, 0, 0, 0])
    markov_chain = MarkovChain(transition_matrix=transition_matrix, initial_distribution=initial_distribution)
    state_distribution = markov_chain.get_state_distribution(iter_time=1000)
    print("平稳状态分布:", state_distribution)
```
