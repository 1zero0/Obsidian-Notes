# 渲染管线原理
游戏中每一帧的画面是如何生成的？
**新一帧渲染循环启动**
**游戏线程（CPU）总管**，负责算逻辑：计算AI、位移、伤害、物理碰撞、网络、UI全部游戏逻辑；输出场景所有物体、特效、镜头数据
**选软线程（CPU）** 绘图策划，整理画画清单；视野剔除、排序绘制层级、打包DrawCall渲染指令队列
**RHI线程（CPU中转）** CPU传令兵，转门和硬件GPU对接下发指令：指令转译，转换成GPU能识别的底层硬件指令
**GPU芯片** 顶点绘制、像素渲染、粒子/光影、画面后处理

手机里图像是怎么来的：
先建模（先建骨骼，2D的贴图）
游戏里：
先画顶点，用无数个点连接成一个3D骨架模型；用无数个三角形的面构成一个人物模型；

GPU接收到渲染指令、模型贴图资源
顶点着色器：运算动作、坐标转换
光栅化：三位三角面拆解成屏幕像素（3D立体图形、拆解成屏幕像素，准备上色。面片越多（精致人物模型、花草），光栅化工作量越大，GPU越吃力）
像素着色器：贴图采样+光影特效上色（GPU发热、卡顿最核心环节，OverDraw、全屏特效、光影全都在这里，光栅化产出一堆带上色像素，本阶段给每一个像素算出最终颜色；同一个像素如果被多层画面反复计算（地面到房子到角色到火焰），就是OverDraw过度绘制，像素着色器重复运算，功耗、发热暴涨）
逐像素测试+半透明颜色融合
存入帧缓存，拼接成基础画面
全屏后处理梅花（光晕、景深、抗锯齿）
完整画面输出到屏幕
循环开启下一帧

# 性能参数（性能狗指标）
CPU：中央处理器：在性能参数中，关于CPU常见的参数就是AvgAppCPU（APP平均CPU使用率）
GPU：图像处理器：在性能参数中，关于GPU常见的参数只有就是AvgGUsage（平均GPU使用率）
Memory：内存：在性能参数中，关于Memory常见的阐述就是AvgMemory（平均内存）、PeakMemory（峰值内存）
FPS：帧率，每秒播放的图片；可用连环画理解，帧率越高，画面感越好；指标：1、1%low：画面的一段时间内，帧数最低的1%的平均帧数；越大约好，越小越卡2、minFPS：一段时间内最低帧的点
Avg（FPS）：平均帧数（一段时间内的平均FPS）
Var（FPS）：帧率方差（一段时间内的FPS方差）
Drop（FPS）：降帧次数（平均没消失相邻两个FPS点下降大于8帧的次数）
Jank：1秒内卡顿次数
Jank（/10min）：平均10分钟的卡顿次数
BigJank（/10min）平均10分钟的严重卡顿次数
FTime：上下帧画面显示时间间隔，帧的耗时
Delta（FTime）：增量好事，平均每小时两帧之间时间差>100ms的次数
Render：渲染器利用率
TilTer：Tilter利用率，顶点利用率
Network：测试目标进程流量
Battery Power功耗（Current电流、Voltage电压、Power功率）
卡顿：当前帧耗时 大于前三帧平均耗时两倍；当前帧耗时大于电影帧耗时（每秒24帧)两倍
同时满足两条件，则认为是一次卡顿Jank.
①Display FrameTime>前三帧平均耗时2倍。
②Display FrameTime>两帧电影帧耗时 (1000ms/24 * 2≈83.33ms)。

同时满足两条件，则认为是一次严重卡顿BigJank.

①Display FrameTime >前三帧平均耗时2倍。
②Display FrameTime >三帧电影帧耗时(1000ms/24 * 3=125ms)。

标准：
帧率：
平均FPS：60帧：高中：平均>=55；低：>=35帧；30帧：高中：平均>=25；低：>=25;90帧：高>=80;中：>=70;低：>=55
最低FPS：60：高中：最低>=45帧；低：>=35帧；30帧：最高中低>=20帧；90：高：>=70；中：>=60;低：>=45；
帧率方差：标准差<=5为优秀；>10则明显感知卡顿（不用管）
jank：有卡顿就需要关注
CPU：安卓：高：<=40%，中：<=50%，低：<=60%；IOS：高中低：<=70%
内存：
平均内存：安卓：高：<=800MB，中：<=700MB，低：<=600；IOS：高：<=900,中：<=700,低：<=550;
内存峰值：不超过设备可用RAM的70%，避免OOM
常驻内存基线：反复操作后，基线涨幅<=5%（无泄漏）
GPU：
GPU平均占用率：平均<=70%，峰值<=90%
DrawCall：移动端单帧建议控制在200~500以内
温度：整机温度<=38
流量：10min内不超过15MB
功耗：重度战斗1小时耗电<=15%

指标大类	具体指标	定义	参考合格标准（手机游戏）
帧率与流畅度	平均 FPS（平均帧率）	每秒渲染的画面帧数，直接决定游戏整体流畅度	
60 帧模式：高端 / 中端机平均≥55 帧，低端机平均≥35 帧
30 帧模式：高端 / 中端机平均≥25 帧，低端机平均≥20 帧
90 帧模式：高端机≥80 帧，中端机≥70 帧，低端机≥55 帧
最低 FPS（最低帧率）	测试场景内出现的瞬时最低帧率，决定玩家能遇到的最差体验	
60 帧模式：高端 / 中端机最低≥45 帧，低端机最低≥35 帧
30 帧模式：高 / 中 / 低端机最低均≥20 帧
90 帧模式：高端机≥70 帧，中端机≥60 帧，低端机≥45 帧
帧率方差（帧率标准差）	帧率的波动幅度，波动越大，玩家越容易感知到顿挫	标准差≤5 为优秀，标准差＞10 会被明显感知卡顿
Jank（卡顿次数）	单位时间内触发的卡顿次数，反映突发卡顿频率	出现 Jank 即需关注优化，无频繁可感知卡顿
CPU 性能	进程 CPU 平均占用	游戏进程占用 CPU 资源的比例，反映 CPU 逻辑计算压力	
安卓：高端机≤40%，中端机≤50%，低端机≤60%
iOS：高 / 中 / 低端机均≤70%
内存性能	平均内存占用	测试周期内游戏占用内存的平均值	
普通场景：高端机≤800MB，中端机≤700MB，低端机≤600MB
重度场景：高端机≤900MB，中端机≤700MB，低端机≤550MB
内存峰值	测试过程中游戏占用内存的最大值，过高会触发闪退	不超过设备可用运行内存（RAM）的 70%，避免 OOM 内存溢出闪退
常驻内存基线	场景稳定后的内存基准值，验证是否存在内存泄漏	反复操作后，内存基线涨幅≤5%，无持续异常增长
GPU 性能	GPU 平均占用	GPU 渲染负载比例，反映画面渲染的压力大小	平均占用≤70%，峰值占用≤90%
Drawcall 数量	CPU 向 GPU 发送的单帧绘制调用次数，主要消耗 CPU 资源，同时增加 GPU 调度压力	移动端单帧建议控制在 200~500 以内
温控	机身温度	持续游戏后机身外壳的温度，验证发烫情况	整机温度≤38℃，无明显烫手问题
流量消耗	10 分钟流量消耗	游戏运行单位时间的移动网络流量消耗	10 分钟内消耗≤15MB
功耗	小时耗电占比	单位时间的电池消耗比例，反映游戏续航表现	重度战斗场景下，1 小时耗电≤15%
