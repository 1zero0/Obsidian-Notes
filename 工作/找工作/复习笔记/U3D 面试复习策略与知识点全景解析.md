# 面试知识不同维度
基础知识：深度维度：L1 了解层 知道是什么 L2 理解层 知道是什么 L3 应用层 能动手做 L4 精通层 能优化能架构
项目：高度维度： H1 
# 三大误区
误区一：无差别覆盖式学习
误区二：只背概念不练手
误区三：项目问题全靠临场发挥
# 知识点深度模型
L1 ：能说出概念名称、基本定义，知道是做什么的（针对非核心知识点，了解就好了）
L2 ：能解释原理，机制，说清“为什么这样做”
L3 ：能写代码、能再项目中使用、能排查问题
L4 ：能做性能优化、分析，底层实现、架构决策
# 优先级
P0 最高 简历项目核心技术 L3+L4 面试必点，点就点深的
P1 高 面试高频考点      L2—L3 几乎每场面试都涉及
P2 中 基础知识体系      L2    保证基础面试不丢分
P3 低 了解即可         L1     知道即可，不深挖
# 高度
H1：what ：Unity有Animator系统，可以播放动画
H2：Why  ：Animator用状态机管理动画切换，因为角色状态多且转换条件复杂，状态机能清晰表达规则
H3：How  ：角色用Animator Controller，怪物用直接播放AnimationClip（状态开销不值得）UI用DOTween（更轻量）
H4：Trade-off：综合考虑团队规模、项目类型、性能预算。大型RPG用Animator+PlayAble做自定义混合，休闲游戏简化为代码驱动状态机

# 三层递进回答结构
第一层：What 描述功能实现 例：我实现了技能释放系统，包含特效播放、伤害计算、状态bufff管理
第二层：How 讲技术方案和关键设计 例：用观察者模式实现技能事件系统，技能释放时发布事件，伤害计算/特效播放/UI更新各自订阅。特效资源用对象池管理避免频繁实例化
第三层：Why & Problem 遇到什么问题、怎么解决的 例：一开始直接在技能类里调伤害计算和特效播放，每加新技能就要改一堆代码。重构为事件驱动后新技能只需要注册新处理器。遇到事件执行顺序不确定导致buff叠加出错，通过优先级队列解决。
